KEY RULES (Apply to ALL modules)
================================================================================

1. SAFE DATA: Only create/edit/delete TEST-prefixed records. Never modify seed data.
2. SCREENSHOTS: Before and after every: Submit, Create, Edit, Approve, Revert, Lock, Unlock.
3. TOASTER MESSAGES: Always capture. Missing expected toaster = BUG.
4. MAKER-CHECKER IDENTITY: Log who made the request and who approved/reverted.
5. REUSABLE: Every scenario must be independently re-runnable.
6. SOFT ASSERTIONS: Use StepLog.check / SoftAssertManager — don't stop on first failure.
7. NO HARDCODING: Use properties files for accounts, config for URLs/credentials.
8. LOCATORS: Use aria-label, role, data-testid. Verify with MCP before hardcoding XPaths.
